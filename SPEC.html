SPECIFICATION

his Spec

Browser history archive & viewer.

Overview

One SQLite archive for all browser history, browsed with a self-built WebUI.

Unified archive

One SQLite file (WAL + FTS5), WebExtensions-style model — HistoryItem + VisitItem.

Incremental sync

Staging snapshots, watermark cursors, append-only. Never opens live browser DBs.

Three frontends

One core: CLI, WebUI (React + @preact/signals), Desktop shell.

Local only

127.0.0.1 only, no telemetry. Plain files — copy to back up.

Directory structure

One core, three frontends.

Architecture

his serve owns the archive, the static WebUI, and the RPC socket; the desktop app only spawns it.

RPC surface

JSON-RPC 2.0 over WS at /rpc — methods mirror the WebExtensions history API, notifications push on the same socket. Same-origin + state-file token only. 

# request / response — id-matched
history.search    { query?, from?, to?, cursor?, limit? } → { items, nextCursor }
history.getVisits { urlId, limit? }                       → VisitItem[]
history.getItem   { id }                                  → { item, visits }
history.deleteUrl { url }                                 → { }              # soft hide · restoreUrl reverts
sources.list                                              → Source[]         # + watermarks
sync.run          { full? }                                → RunHandle        # progress push on hold
sync.status                                               → LastRun

# notifications — same socket, no id
sync.progress     { source, phase, parsed, upserted }     # on hold — not implemented
db.changed        { }                                     # clients refetch open views

Runtime state

The running instance keeps ~/.his/state.json; one home = one archive = one instance.

Lifecycle

Written once the port is bound, removed on clean shutdown.

Liveness

Readers verify the PID is alive (kill(pid, 0)) and prune dead-PID files in place.

Location

~/.his/state.json — pid, port, url, db path, /rpc token. A second his serve just reports the running URL. The home also holds history.db and staging copies; distinct archives = distinct homes (HIS_HOME).

Write path

One writer per process (WAL + busy_timeout); sync runs via his sync or sync.run RPC. WebUI has no direct DB access.

Data model

WebExtensions-leaning shapes in SQLite — urls = HistoryItem aggregate, visits = VisitItem events. Epoch ms, Chromium transition enums.

Schema

-- history.db · WAL · foreign_keys=ON · append-only (+ soft delete)
CREATE TABLE source_profiles (          -- registered browser profiles · identity = (browser, profile)
  id            INTEGER PRIMARY KEY,
  browser       TEXT    NOT NULL,       -- user-facing slug · chrome, brave, ...
  profile       TEXT    NOT NULL,       -- slugified dir · Default, vpw8f8gt.default-release, ...
  kind          TEXT    NOT NULL,       -- engine · derived from browser
  display_name  TEXT,
  profile_path  TEXT    NOT NULL,
  UNIQUE(browser, profile)
);

CREATE TABLE urls (                     -- HistoryItem · URL aggregate
  id               INTEGER PRIMARY KEY,
  url              TEXT    NOT NULL UNIQUE,
  title            TEXT,                -- last seen
  first_visit_time INTEGER NOT NULL,    -- epoch ms
  last_visit_time  INTEGER NOT NULL,    -- epoch ms
  visit_count      INTEGER NOT NULL DEFAULT 0,
  typed_count      INTEGER NOT NULL DEFAULT 0,
  hidden_at        INTEGER              -- soft delete · NULL = visible
);

CREATE TABLE visits (                   -- VisitItem · one row per visit
  id                INTEGER PRIMARY KEY,
  url_id            INTEGER NOT NULL REFERENCES urls(id),
  visit_time        INTEGER NOT NULL,   -- epoch ms
  transition        TEXT    NOT NULL,   -- Chromium enum · LINK / TYPED / ...
  source_profile_id INTEGER NOT NULL REFERENCES source_profiles(id),
  source_visit_id   INTEGER NOT NULL,   -- native visit id · takeout: stable hash
  UNIQUE(source_profile_id, source_visit_id)
);
CREATE INDEX idx_visits_visit_time        ON visits(visit_time DESC);
CREATE INDEX idx_visits_url_id_visit_time ON visits(url_id, visit_time DESC);
CREATE INDEX idx_urls_last_visit_time     ON urls(last_visit_time DESC);      -- timeline sort

CREATE TABLE profile_watermarks (       -- incremental cursors per profile
  source_profile_id    INTEGER PRIMARY KEY REFERENCES source_profiles(id),
  last_source_visit_id INTEGER NOT NULL DEFAULT 0,
  source_id_offset     INTEGER NOT NULL DEFAULT 0,  -- += last_raw_id on clear
  last_run_at          INTEGER
);

CREATE VIRTUAL TABLE urls_fts USING fts5(
  title, url,
  content='urls', content_rowid='id',
  tokenize='trigram'                    -- SQLite >= 3.34 · trigger-maintained
);

CREATE TRIGGER urls_fts_after_insert AFTER INSERT ON urls BEGIN
  INSERT INTO urls_fts(rowid, title, url) VALUES (new.id, new.title, new.url);
END;

CREATE TRIGGER urls_fts_after_delete AFTER DELETE ON urls BEGIN
  INSERT INTO urls_fts(urls_fts, rowid, title, url) VALUES ('delete', old.id, old.title, old.url);
END;

CREATE TRIGGER urls_fts_after_update AFTER UPDATE ON urls BEGIN
  INSERT INTO urls_fts(urls_fts, rowid, title, url) VALUES ('delete', old.id, old.title, old.url);
  INSERT INTO urls_fts(rowid, title, url) VALUES (new.id, new.title, new.url);
END;

Design notes

HistoryItem / VisitItem split

urls = URL aggregate, visits = events — WebExtensions shape 1:1, RPC responses need no reshaping.

Dedup & reset detection

Source MAX(id) shrinking = history cleared → source_id_offset += last_raw_id (Gateway 式). Takeout has no native ids — stable hash of (url, time). Watermarks advance only after a successful commit.

Time = epoch ms

Adapters convert WebKit µs / PRTime µs / Cocoa s / Takeout µs on the way in. Alt: Unix seconds — WebExtensions unit wins.

Transitions normalized

WebExtensions history.TransitionType (lowercase: link / typed / ...) is the axis; Firefox / Safari / Takeout map at sync.

Soft delete

urls.hidden_at — reads filter hidden_at IS NULL; history.deleteUrl / restoreUrl flip it. Alt: tombstone + compact / immutable.

Search: trigram

External content on urls (title, url), trigger-maintained; <3 chars → LIKE; hits join hidden_at IS NULL. Alt: unicode61 / contentless.

Favicons — favicons.db

On hold — favicon storage & serving is deferred for now; implementation removed, spec kept as designed.

-- separate file · permanent store · no TTL
CREATE TABLE favicons (
  id          INTEGER PRIMARY KEY,
  host        TEXT    NOT NULL UNIQUE,    -- www-stripped (+ root fallback at read)
  data        BLOB    NOT NULL,
  data_type   TEXT    NOT NULL,           -- png | svg | ico | webp | jpeg | gif
  width       INTEGER NOT NULL DEFAULT 0, -- best quality wins · never downgraded (svg = 0)
  updated_at  INTEGER NOT NULL            -- epoch ms · harvest time = diff baseline
);

Quality upsert

Overwrite only when better (SVG > width > newer) — no downgrade, no TTL; refresh rides the history-delta harvest phase.

Why separate

Not rebuildable — dropping the file loses icons (recent slice only); back up with history.db. Keeps it lean. Alt: page-level rows (Chrome 式) / same-DB blobs.

Sync

Periodic (6h) change-check triggered; snapshots only — live browser DBs are never opened.

Trigger

6h periodic; per-target fingerprint gate (mtime/size + sidecars, persisted in the DB) — unchanged targets skip snapshot; catch-up sync at startup. Alt: file events / OS scheduler.

Pipeline

fingerprint gate → snapshot → parse → upsert → watermark. One transaction per profile; INSERT OR IGNORE keeps re-sync idempotent.

Snapshot

SQLite VACUUM INTO from a read-only source handle → staging — used pages only, WAL folded, page-atomic. Fallback (hot journal / open failure): copy main + sidecars → ~/.his/staging/<source>/<profile> and fold on open. The live DB is never written.

Watermarks

Advance only after a successful commit. Source MAX(id) shrinking = history cleared → source_id_offset += last_raw_id.

Considerations

Everything settled — alternatives live in their sections. Decision log and deferred minor items below.

Decisions

Settled

  • Sync runs both ways — standalone his sync writes directly, sync.run over RPC runs in-process; accidental overlap covered by WAL + busy_timeout
  • /rpc accepts same-origin + state-file token only
  • Page bodies out of scope — metadata only, no WARC / WACZ
  • Dedup key = (source_profile_id, source_visit_id) — watermark incremental with reset detection
  • Sync cadence = 6h periodic + per-target fingerprint gate (unchanged targets skip snapshot) + a startup catch-up sync
  • Favicon store = permanent harvest — one best icon per host (SVG > width > newer), history-delta driven, no TTL / no favicon cursor → on hold: implementation removed for now

Deferred

  • CLI query output formats — JSON / CSV / table
  • Desktop webui bundling — shipped dist vs dev vite proxy
  • Favicon harvest / storage — on hold: online favicon fetch (Google S2 / origin /favicon.ico fallback · privacy policy pending) stays frozen until favicon storage ships
