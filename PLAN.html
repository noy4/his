IMPLEMENTATION PLAN

his plan

Plan for the his core, CLI, and desktop shell — PLAN.web covers the WebUI.

Roadmap

Phases follow the dependency chain: model → DB → sync → sources → CLI → serve/RPC → desktop. Core ships before its consumers. The WebUI stays on mocks until Phase 6 lands. PLAN.web then swaps its mock api.ts for a real WS client.

Phase 1 — Model P1 · core
The shared vocabulary. Every package and the WebUI type against these shapes.
core/ scaffold
package.json · tsconfig · strict TS — no frontends imported
model.ts
HistoryItem · VisitItem — WebExtensions shape 1:1 · epoch ms everywhere
Transition axis
Chromium enums (LINK / TYPED / ...) — natives map onto it at sync
Phase 2 — DB layer P1 · core
history.db and favicons.db live here. One writer per process.
schema.sql
urls · visits · source_profiles · profile_watermarks · urls_fts trigram — favicon_cache in favicons.db
open.ts
open · WAL · busy_timeout · foreign_keys · migrations
query.ts
search (trigram, <3 chars → LIKE) · timeline · keyset pagination · hidden_at IS NULL filter
Phase 3 — Sync engine P1 · core
Incremental, snapshot-only. Live browser DBs are never opened.
snapshot.ts
copy sidecars + main → ~/.his/staging/<source>/<profile> · open folds one file
watermarks.ts
per-profile cursor · MAX(id) shrink = cleared → source_id_offset += last_raw_id
run.ts
snapshot → parse → upsert → watermark · one tx per profile · INSERT OR IGNORE · watermark advances only after commit
Phase 4 — Sources P2 · core
One adapter per vendor. All normalize onto epoch ms + Chromium transitions. Unmappable values keep the raw string in source_transition.
chromium.ts
Chrome / Edge / Brave / Vivaldi / Arc · WebKit µs (1601) → ms · native enum
firefox.ts
places.sqlite · PRTime µs ÷ 1000 · Places 1–8 → enum
safari.ts
History.db · Core Data s (2001) → conservative LINK, raw kept
takeout.ts
BrowserHistory.json · 3 layouts · time_usec ÷ 1000 · (url, time) stable hash ids
Phase 5 — CLI commands P2 · cli
The his binary. Thin arg parsing over core. sync writes the archive directly. query is a read-only walk.
bin.ts
arg parsing · his [sync|serve|query|status|stop] · --home (env HIS_HOME)
sync paths
per-source counts · errors exit 1 · --source <kind> · --full ignores watermarks (idempotent)
query command
history.search against history.db → JSON · --url --from --to --limit
Phase 6 — Serve & RPC P2 · cli
One process owns the archive, the static WebUI, and /rpc. Desktop only spawns it.
server/index.ts
static dist · binds 127.0.0.1 · GET /favicon/<eTLD+1> from favicons.db
server/rpc.ts
JSON-RPC 2.0 over WS /rpc · dispatch to core · same-origin + token only · pushes db.changed / sync.progress
server/state.ts
writes ~/.his/state.json · pid liveness kill(pid, 0) · stale prune · port +1 on conflict
Watch loop
file watch on profile DBs · FSEvents / mtime poll · 5 s debounce → sync
Phase 7 — Desktop shell P3 · desktop
A macOS menu bar client. One window. Spawns his serve; stops it on quit. No embedded logic.
src/main.ts
single-instance lock · spawn / stop serve · BrowserWindow → serve URL
src/tray.ts
Sync Now · Open · Quit his — sync.progress shown in the tooltip
Lifecycle
reads state.json for port / token · tray actions respawn serve when down

Contracts & seams

Small, stable contracts between packages. Frontends never reach past them.

RPC surface = core's contract

core implements history.* / sources.* / sync.*. cli/server/rpc.ts is a thin dispatcher.

state.json — serve ↔ desktop

Written once the port is bound, removed at shutdown. Desktop spawns when absent, reports when present. One home = one archive = one instance (HIS_HOME).

WebUI seam lands here

One import swap at the api.ts seam. Views don't change. Push (db.changed) drives the refetch signals.

favicons.db — rebuildable

Rebuildable at any time. Domain-keyed by eTLD+1; best-width upsert; 30-day TTL swept after sync. Served at /favicon/<eTLD+1>; 404 → letter tile.

P1 lands independently of the WebUI. Phase 6 serve is the WebUI's last prerequisite — PLAN.web Phases 6–7 go real after it.
