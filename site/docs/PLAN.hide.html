IMPLEMENTATION PLAN

his · hide URL patterns

指定 URL パターンにマッチする履歴を全ビュー・集計から除外する設定 — settings テーブル + hidden_urls テーブル。

status 実装済 — core / server / webui。実 RPC で動作（テスト 10/10）

Overview

ユーザーが指定した URL / ホスト名パターンを「非表示」として扱い、Urls・Visits・Dashboard・GitHub・検索の全表示と集計から除外する。設定は settings テーブルに保存し、該当 URL を hidden_urls テーブルに materialize してフィルタする方式。

実装: settings（KV）+ hidden_urls（派生）を migration 006 で追加。読取りは全クエリで hidden_urls を除外、書込みは保存時の全再計算と sync 時の新規判定。WebUI は Settings ビューで編集。

目的

見せたくないサイトをアーカイブに残したまま、UI と集計から隠す。SPEC の「Hidden rows are never returned.」を実装する。

範囲

core のルール評価・DB フラグ・全読取りクエリ、server の RPC 2 本、webui の Settings ビュー。

非対象

private ルール(liveness / AI 送信)は今回入れない。favicons 等 on-hold 機能との連携もしない。依存追加なし。

保存

history.db 内の settings テーブル。1 home = 1 archive = 1 設定。CLI / server / sync が同一データを参照。

Decisions

各 D は Decision(設計判断)。番号は討議・引用用のラベルで、却下時は「D2 を却下」のように参照する。

D1 設定の保存場所

history.db に settings(key TEXT PRIMARY KEY, value TEXT NOT NULL) を新設(migration 006)。key hidden_patterns に JSON string[] を格納（trim / 小文字化 / 重複排除 / 上限 500 の正規化はコード側）。1 home = 1 archive = 1 設定で、server / CLI / sync が同一データを参照。~/.his/config.json 案は不採用。

D2 マッチ規則

case-insensitive / trim / 空行無視 / 重複排除 / 上限 500。壊れたパターンでも throw しない。hostname マッチと URL glob の二段構え(下の Syntax 参照)。

D3 フィルタ方式

派生は hidden_urls(url_id INTEGER PRIMARY KEY REFERENCES urls(id)) に materialize（urls の列ではなく別テーブル）。読取りは NOT EXISTS (SELECT 1 FROM hidden_urls WHERE url_id = urls.id) を足すだけで FTS join・集計・GitHub に一律適用。列方式を避ける理由は、urls の AFTER UPDATE FTS トリガが再計算のたびに無駄な再インデックスを起こすため。query-time 動的評価は不採用。

D4 RPC

settings.get → { hiddenPatterns, hiddenCount } / settings.set { hiddenPatterns } → 正規化して保存・hidden_urls 再計算し同じ形を返す。client は settings.get() / settings.set() の名前空間で呼ぶ。hiddenCount は Settings 画面の表示のみに使い、集計には混ぜない。保存後 broadcast('settings.changed')(任意)。

D5 UI

nav に新 View settings。ページ見出しは置かず「セクション見出し＋行」構成（SettingsSection* / SettingsRow*）。textarea(1 行 1 パターン)＋右寄せ Save、件数/状態は SettingsMeta。ボタンは ui/button の preset（buttonPrimary / buttonSmGhost）。

D6 再計算タイミング

(a) ingest 時に新規 URL を判定、(b) 設定保存時に全 row を再計算(変更行のみ UPDATE・1 transaction)。(a) があるため「設定変更 → 新規取り込み」も正しい。

Pattern syntax

1 行 1 パターン。判定はパターンに / があるかで分岐する。

# hostname マッチ — スラッシュなし
example.com          → example.com と全サブドメイン
*.bank.com           → bank.com の任意サブドメイン
10.0.*               → ワイルドカード

# path glob — スラッシュあり（scheme を除いた URL に照合）
github.com/*/pull/*  → github.com/o/r/pull/12 にマッチ

# scheme を含むパターンは URL 全体に照合
https://*.example.com/*

# 正規表現メタ文字は自動エスケープ · * のみワイルドカード
bare ドメインはサブドメインも含む(example.com ≒ example.com + *.example.com)。slash パターンは先頭 scheme:// を除いた URL に当てる（github.com/*/pull/* は https://github.com/… にマッチ）。
