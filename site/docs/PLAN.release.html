RELEASE PLAN

his release plan

Ship the CLI and Desktop as verified, installable releases.

First release

Proposed scope, pending decisions on package name, platforms, runtime and signing. Start with a prerelease; publish a stable release only after testing the installed artifacts.

CLI · npm

Publish an installable package with the runtime assets needed for sync, query and serve. Define and test its Node requirement.

Desktop · macOS

Publish a signed and notarized DMG on GitHub Releases. The installed app must work without a repository checkout or system Node.

Windows, Linux, an independent download server and automatic updates are outside the proposed first release. Manual reinstall is the initial update path.

Starting point

Not yet distributable

Packages are private and the CLI points to TypeScript source. Desktop starts the repository's CLI using node from PATH. Packaging and release workflows are not configured.

Release blockers

Bundle the WebUI and SQL migrations, verify clean builds, and resolve process ownership and access to sensitive history data before publishing.

At investigation time, local main was 36 commits ahead of origin/main. Review and publish the intended commit before tagging; do not assume the remote contains the release candidate.

Roadmap

Define the contract, create self-contained artifacts, harden them, then release the exact artifacts that passed verification.

Phase 1 — Release contractP0 · decisions
Fix the support and security boundaries before choosing build and publish settings.
Names & versions
npm name and ownership · app ID · version and tag convention · prerelease channel
Supported environments
Node version · macOS minimum and architectures · verify SQLite FTS5
First-run consent
Select sources explicitly · explain that an empty selection syncs nothing
Trust & ownership
Define local-user threat model · data retention · shared server lifetime
Phase 2 — CLI packageP0 · npm
Make the CLI runnable outside the workspace without source-relative dependencies.
Build & manifest
JavaScript bundle · executable entry · Node requirement · bundled workspace dependencies
Runtime assets
Package WebUI and SQL migrations alongside the CLI bundle
Packed install
Automated isolated install · Takeout sync and query · server, WebUI, status and stop
Getting started
Document local package installation, source selection, CLI commands, data and permissions
Phase 3 — Desktop packageP0 · macOS
Ship a self-contained Electron application, not a wrapper around a developer checkout.
Clean build inputs
Tracked files build without a checked-in renderer entry · verified using existing dependencies
Reproducible release toolchain
Node 22.22.3 · pnpm 12.6.0 verified locally on macOS · pin and verify release CI separately
Self-contained runtime
Unsigned macOS app includes Electron, CLI, WebUI, migrations and tray assets · isolated arm64 packaged smoke test passes
Sign & notarize
App ID, icon and DMG · Developer ID signing · Apple notarization and stapling
Startup diagnostics
Server spawn failures, stderr and timeout reported; packaged asset and runtime failures still require verification
Phase 4 — Safety & reliabilityP0 · hardening
Browser history is sensitive. Verify behavior at process, user and data boundaries.
Local access
Review loopback token exposure and Electron navigation against the chosen threat model
Data protection
Set and test permissions · document snapshots, deletion, backup and favicon requests
Process ownership
Single instance · race-safe server ownership · PID reuse · do not inadvertently stop a shared server
Actionable failures
Report sync failures and timeouts · explain Safari permission denial and retry
Phase 5 — CI & releaseP0 · automation
Separate artifact creation and verification from publication; promote the tested artifacts without rebuilding.
PR gates
Typecheck and tests · supported OS/Node matrix · new and existing database migrations
Artifact gates
Clean CLI install · packaged Desktop smoke test · checksum · signature and notarization checks
Approved publication
Review release commit and tag · publish npm with trusted publishing · attach DMG to GitHub Release
Recovery
Define partial-publish retry, prerelease dist-tags and rollback or replacement release procedure
Phase 6 — Prerelease to stableP1 · validation
Release a prerelease first. Promote only after a clean-machine test for each supported target.
Install & first run
No checkout or system Node for Desktop · choose sources · sync · search · restart
Upgrade & recovery
Existing DB migration · reinstall · uninstall · permission denial · shared server behavior
Stable gate
All target checks pass · blockers resolved · release notes and known limitations published

Reference
