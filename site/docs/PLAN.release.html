RELEASE PLAN

his release plan

Ship the CLI and Desktop as verified, installable releases.

First release

Decisions are settled: the CLI publishes as @noy4/his, Desktop as an ad-hoc signed macOS 12+ arm64 DMG with no Developer ID. Validate the installed artifacts on a clean machine, then publish the stable 0.1.0 release; there is no prerelease channel.

CLI · npm

Publish an installable package with the runtime assets needed for sync, query and serve. Define and test its Node requirement.

Desktop · macOS

Publish an ad-hoc signed DMG on GitHub Releases. It is not notarized, so the first launch is approved once in System Settings → Privacy & Security. The installed app must work without a repository checkout or system Node.

Windows, Linux, an independent download server, automatic updates and isolation from other local users are outside the proposed first release. Manual reinstall is the initial update path.

Starting point

Not yet distributable

Packages are private and the CLI points to TypeScript source. Desktop starts the repository's CLI using node from PATH. Packaging and release workflows are not configured.

Release blockers

Bundle the WebUI and SQL migrations, verify clean builds, and resolve process ownership and access to sensitive history data before publishing.

At investigation time, local main was 36 commits ahead of origin/main. Review and publish the intended commit before tagging; do not assume the remote contains the release candidate.

Roadmap

Define the contract, create self-contained artifacts, harden them, then release the exact artifacts that passed verification.

Phase 4 — Safety & reliabilityP0 · hardening
Browser history is sensitive. Verify behavior at process, user and data boundaries.
Local access
Explicit webPreferences · window shows only the loopback WebUI · external links go to the OS browser · isolation from other local users deferred
Data protection
Additional permissions and documentation for snapshots, deletion, backup and favicon requests · deferred
Desktop process ownership
Single instance · stop only the server started by Desktop · CLI uses Ctrl+C
Concurrent startup
Startup races and stale state · deferred
Manual sync errors
Show sync failure details in Desktop and WebUI
Background sync errors
Show the latest failed sync in Sources · refresh while the page is open
Actionable failures
Explain Safari permission denial and retry · deferred
Phase 5 — CI & releaseP0 · automation
Separate artifact creation and verification from publication; promote the tested artifacts without rebuilding.
Release checks
Lint · typecheck (incl. WebUI) · tests · generated DB types · run inside the release workflow, no PR workflow
Artifact gates
Clean CLI install · packaged Desktop smoke test · checksum and signature verification — automated in the release workflow · first-launch approval still needs a clean machine
Approved publication
Tag/version check · publish the tested tarball with npm trusted publishing (id-token: write, next for prereleases) · attach the DMG and checksum to the GitHub Release · needs the @noy4 scope and a trusted publisher configured on npm
Recovery
Retry only the failed job — npm and the release upload are independent. A bad DMG is replaced on the release (--clobber); a bad npm version is deprecated and superseded by the next patch, since a published version can never be reused; latest rolls back with npm dist-tag add while prereleases stay on next

Stable gate
All target checks pass · blockers resolved · release notes and known limitations published
