IMPLEMENTATION PLAN

his plugin plan

Package the GitHub and YouTube views as plugins — frontend and backend half in one module.

Plugin shape

GitHub and YouTube become self-contained plugins — frontend and backend half in one module, loaded by a build-time registry.

Build-time registry

Plugins are imported and listed in a registry. Type-safe, one bundle, shared singletons preserved. Chosen.

Runtime load

Drop-in without a rebuild — deferred. The essential costs are noted below; not worth it for a local, first-party app.

Frontend contract

A plugin owns its view, its model, and (from Phase 3) its API slice. The app only knows the registry. 

// webui/src/plugins/types.ts — the contract
export interface ViewPlugin {
  id: string                        // 'github' | 'youtube'
  label: string
  icon: IconComponent
  nav?: { after?: string; group?: 'insights' }   // placement
  View: ComponentType<{ app: AppModel }>
}

// webui/src/plugins/registry.ts — the one place to add a view
export const VIEW_PLUGINS: ViewPlugin[] = [github, youtube]

// webui/src/plugins/github/index.ts — a plugin manifest
export const github: ViewPlugin = {
  id: 'github',
  label: 'GitHub',
  icon: GithubIcon,
  nav: { after: 'urls' },
  View: GithubView,
}

Runtime load — essential costs

Memo. If drop-in plugins are ever required, these are irreducible — not implementation details.

Shared singletons

React and @preact/signals-react must be one instance across host and plugin. A second copy breaks reactivity — needs an import map or Module Federation shared scope.

Build-time tooling

unplugin-icons inlines icons at build time. A runtime plugin cannot use it — it must ship components/SVG through the contract instead.

Shared internals

Plugins lean on components/view/*, components/ui/* and lib/*. Those must become a published SDK, or the plugin is not self-contained.

Trust

Plugin code runs in-process with full archive access — no sandbox. Acceptable for first-party code, unsafe for third-party distribution.

Lifecycle

Migration ownership, version skew, RPC namespace collisions, load/unload — all fall out of dynamic loading, none from the registry.

Plugin roadmap

Frontend first — GitHub is the canary. Then the backend half joins the same module.
