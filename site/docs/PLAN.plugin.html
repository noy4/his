IMPLEMENTATION PLAN

his plugin plan

Package the GitHub and YouTube views as plugins — frontend and backend half in one module.

Plugin shape

GitHub and YouTube become self-contained plugins — frontend and backend half in one module, loaded by a build-time registry.

Build-time registry

Plugins are imported and listed in a registry. Type-safe, one bundle, shared singletons preserved. Chosen.

Runtime load

Drop-in without a rebuild — deferred. The essential costs are noted below; not worth it for a local, first-party app.

Frontend contract

A plugin owns its view, its model, and its API wrapper (built from app.rpc). The app only knows the registry. 

// webui/src/plugins/types.ts — the contract
import type { RpcCall } from '@/lib/rpc-transport'

export interface ViewContext {
  rpc: RpcCall
}

export interface ViewPlugin {
  id: string                        // 'github' | 'youtube'
  label: string
  icon: IconComponent
  View: (props: { app: ViewContext }) => ReactNode
}

// webui/src/plugins/registry.ts — fixed order = nav order
export const VIEW_PLUGINS: ViewPlugin[] = [github, youtube]

// webui/src/plugins/github/index.ts — a plugin manifest
export const github: ViewPlugin = {
  id: 'github',
  label: 'GitHub',
  icon: GithubIcon,
  View: Github,
}

Backend contract

// server/src/plugins/types.ts — the node half
export interface ServerPlugin {
  name: string                      // 'github' | 'youtube'
  handlers: (ctx: { db }) => Record<string, Handler>
}

// server/src/plugins/index.ts
export const PLUGINS: ServerPlugin[] = [github, youtube]

Runtime load — essential costs

Memo. If drop-in plugins are ever required, these are irreducible — not implementation details.

Shared singletons

React and @preact/signals-react must be one instance across host and plugin. A second copy breaks reactivity — needs an import map or Module Federation shared scope.

Build-time tooling

unplugin-icons inlines icons at build time. A runtime plugin cannot use it — it must ship components/SVG through the contract instead.

Shared internals

Plugins lean on components/view/*, components/ui/* and lib/*. Those must become a published SDK, or the plugin is not self-contained.

Trust

Plugin code runs in-process with full archive access — no sandbox. Acceptable for first-party code, unsafe for third-party distribution.

Lifecycle

Migration ownership, version skew, RPC namespace collisions, load/unload — all fall out of dynamic loading, none from the registry.

Packaging prep

Before the frontend and backend halves can share one package, webui needs a clean kit boundary. This section studies the move — no code changes yet.

Blockers

@/ alias

A package cannot use webui's alias. Kit internals need relative imports or their own @kit/*.

Tailwind scanning

index.css is @import 'tailwindcss' and only scans webui/src. Add @source for each package or classes are never generated.

~icons/*

unplugin-icons resolves only in webui's Vite. Consume workspace packages as source, or pass icons as props.

Singletons

React and @preact/signals-react must stay one instance — model them as peerDependencies.

RpcCall split

RpcCall lives in lib/rpc-transport.ts. Move the type to the kit contract; keep the transport class in webui.

Node feature move

core/src/features/{github,youtube} must move into each plugin's ./node; parsers go to a shared ./parse.
