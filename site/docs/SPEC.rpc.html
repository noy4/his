SPEC

his · rpc

/rpc（JSON-RPC 2.0 over WS）にパス制限・Origin 検証・トークンを導入するための仕様とプラン。

Overview

現状 /rpc はどのパス・どの Origin からでも WebSocket を受理する。ブラウザで開いた任意のサイトからローカル RPC を叩ける状態なので、ループバック前提をコードで強制する。

目的

任意サイトから history.search 等を呼べないようにする。same-origin をサーバ側で検証し、非ブラウザ経路はトークンで絞る。

範囲

ゲートは server/src/rpc.ts、トークン発行は server/src/index.ts、保存権限は core/src/state.ts、WebUI への配布は server/src/app.ts。

非目標

マルチユーザ認証・リモート公開・TLS。LAN へ出す場合はリバースプロキシ側で認証を付ける前提のまま。

完了条件

悪意ある Origin からの WS が拒否され、WebUI / CLI / Electron は従来どおり動作し、state.json が 0600 になる。

Threat model

守る対象は履歴そのもの（URL・title・訪問時刻・GitHub 可視情報）と、ローカル経路が漏らす情報。

#攻撃者現状対策後
Aブラウザで開いた任意サイト（広告 iframe 含む）接続でき、履歴を読み出せるOrigin 不一致を 403 で拒否
B同一マシンの別プロセス・別ユーザ接続できるトークン必須
CLAN / リモートloopback 固定で到達不可変更なし

A が本命。WebSocket は同一生成元ポリシーの対象外で、ブラウザは任意の Origin から ws://127.0.0.1:4477/ に接続できてしまう。したがって防御線はサーバ側の Origin 検証だけになる。

Design

3段のゲートを上から順に適用する（早い段で落とすほど安い）。

1. パスゲート

req.url が /rpc 以外なら socket.destroy()。surface を 1 経路に絞る。

2. Origin ゲート

許可するのは起動時に確定した origin —http://127.0.0.1:<port> と http://localhost:<port>。port は衝突時に +1 されるため実際に bind したポートを使う。不一致は 403。
Origin ヘッダが無い場合（スクリプト・CLI・手動クライアント）は Origin 検証を素通りするため、次のトークンで絞る。

3. トークン

起動時に crypto.randomBytes(32).toString('base64url') を発行し state.json に 0600 で保存。検証は crypto.timingSafeEqual（長さ不一致は即 false）。運搬は /rpc?token=…（ブラウザは WS ハンドシェイクに任意ヘッダを付けられないため）。Origin の有無にかかわらず全接続で必須。

4. WebUI への配布

server/src/app.ts が entry（isEntry）応答時に <script>window.__HIS__={token}</script> を </head> 直前へ注入し、WebUI にトークンを渡す。dev は vite plugin が同じものを state から差し込む。

5. state.json の権限

fs.writeFileSync(file, data, { mode: 0o600 })（既存ファイルは chmod）。トークンが入るため必須。

Risks & open questions

論点

論点選択肢現時点の判断
トークンの運搬クエリ / サブプロトコル / Cookieクエリ。ブラウザはヘッダを足せず、Cookie は CSRF 面が広がる
Origin 欠落拒否 / トークンあれば許可トークン必須（全接続共通）。スクリプト用途は残る
許可オリジン127.0.0.1 のみ / localhost も両方。ブラウザは localhost で開かれ得る
vite devdev ポートも許可 / proxy で書換proxy で Origin を serve origin に書換 + state からトークン注入

リスク

既存 state.json との互換

トークン無しの state が残っていると起動時に検証が揺れる。起動時に読み直して無ければ発行する順序にする。

壊したときの戻し

ゲートは rpc.ts の 1 箇所なので、Phase 単位で revert 可能。Phase 1 のみでも A の脅威は消える。

トークンの寿命

揮発（起動ごと再発行）なので、再起動で開いたままの WebUI は再接続時に失敗する。リロードで回復する想定。

残余リスク

同一ユーザ権限のプロセスは state.json を読める（0600 は他ユーザを止めるだけ）。マルチユーザ前提の防御は非目標。
