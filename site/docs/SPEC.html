SPECIFICATION

his Spec

Browser history archive & viewer.

Overview

One SQLite archive for all browser history, with WebUI.

Unified archive

One SQLite file (WAL + FTS5), WebExtensions-style model — HistoryItem + VisitItem.

Incremental sync

Snapshot copies + checkpoint cursors.

Three frontends

CLI, WebUI, Desktop shell.

Local only

127.0.0.1 only

Architecture

his serve owns the archive, the WebUI, and the RPC socket. Desktop just spawns it.

One BrowserWindow — loads the serve URL. Close hides it.

Reuses a running instance, else spawns + waits. Tray actions respawn when down.

Data model

URLs and visits in one SQLite file.

Schema

-- history.db · WAL · foreign_keys=ON
CREATE TABLE source_profiles (          -- browser profiles
  id            INTEGER PRIMARY KEY,
  browser       TEXT    NOT NULL,       -- chrome, brave, ...
  profile       TEXT    NOT NULL,       -- profile dir
  kind          TEXT    NOT NULL,       -- engine
  profile_path  TEXT    NOT NULL,
  UNIQUE(browser, profile)
);

CREATE TABLE urls (                     -- HistoryItem
  id               INTEGER PRIMARY KEY,
  url              TEXT    NOT NULL UNIQUE,
  title            TEXT,                -- last seen
  first_visit_time INTEGER NOT NULL,    -- epoch ms
  last_visit_time  INTEGER NOT NULL,
  visit_count      INTEGER NOT NULL DEFAULT 0,
  typed_count      INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE visits (                   -- VisitItem
  id                INTEGER PRIMARY KEY,
  url_id            INTEGER NOT NULL REFERENCES urls(id),
  visit_time        INTEGER NOT NULL,   -- epoch ms
  transition        TEXT    NOT NULL,   -- LINK / TYPED / ...
  source_profile_id INTEGER NOT NULL REFERENCES source_profiles(id),
  source_visit_id   INTEGER NOT NULL,   -- native id · takeout: hash
  UNIQUE(source_profile_id, source_visit_id)
);
CREATE INDEX idx_visits_visit_time        ON visits(visit_time DESC);
CREATE INDEX idx_visits_url_id_visit_time ON visits(url_id, visit_time DESC);
CREATE INDEX idx_urls_last_visit_time     ON urls(last_visit_time DESC);      -- timeline sort

CREATE TABLE sync_checkpoints (         -- sync cursors
  source_profile_id    INTEGER PRIMARY KEY REFERENCES source_profiles(id),
  last_source_visit_id INTEGER NOT NULL DEFAULT 0,
  source_id_offset     INTEGER NOT NULL DEFAULT 0,  -- += last_raw_id on clear
  last_fingerprint     TEXT,                -- change gate
  last_run_at          INTEGER
);

CREATE VIRTUAL TABLE urls_fts USING fts5(
  title, url,
  content='urls', content_rowid='id',
  tokenize='trigram'                    -- trigger-maintained
);

CREATE TRIGGER urls_fts_after_insert AFTER INSERT ON urls BEGIN
  INSERT INTO urls_fts(rowid, title, url) VALUES (new.id, new.title, new.url);
END;

CREATE TRIGGER urls_fts_after_delete AFTER DELETE ON urls BEGIN
  INSERT INTO urls_fts(urls_fts, rowid, title, url) VALUES ('delete', old.id, old.title, old.url);
END;

CREATE TRIGGER urls_fts_after_update AFTER UPDATE ON urls BEGIN
  INSERT INTO urls_fts(urls_fts, rowid, title, url) VALUES ('delete', old.id, old.title, old.url);
  INSERT INTO urls_fts(rowid, title, url) VALUES (new.id, new.title, new.url);
END;

Sync

Sync the configured targets.

targets → gate → snapshot → parse → upsert → checkpoint

Targets come from settings.sync_targets; an empty list syncs nothing. his sync --target overrides them once.

Gate

Skips targets whose fingerprint (mtime/size) matches the stored sync_checkpoints.last_fingerprint.

Snapshot

The live DB is locked by the browser, so sync reads a stable copy. path: ~/.his/snapshots/<source>/<profile>

  1. Copy: VACUUM INTO from a read-only handle — WAL folded.
  2. Fallback: on hot journal / open failure, copy main + sidecars, fold on open.

Parse

Normalizes each source's rows into the schema.

Upsert

INSERT OR IGNORE keeps re-sync idempotent.

Checkpoint

Advances the cursor after each committed run. Reset: if the source's max id shrinks (history cleared), bump source_id_offset += last_raw_id so old ids can't collide.

Trigger

6h periodic + startup catch-up.
